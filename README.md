# VEGAS CN — A股

CN is the A-share repository. Its seven common display systems and visual assets are based on the Media asset library; its A-share data, scanning, signal, and Bark modules are independently implemented and run inside CN.

## Seven systems
1. K-line renderer and Vegas EMA overlay — Media K-line renderer, connected to Tencent QFQ daily candles.
2. Shared viewport and gestures — Media pan/pinch/zoom, viewport anchoring and page lifecycle, with a CN-only persistence namespace; double-tap pauses/resumes automatic K-line/Logo rotation.
3. Rolling market cards — Media card presentation and interaction, populated from the A-share CN500 snapshot and latest-session signals.
4. Logo and countdown — Media logo module adapted to display the selected A-share name/code and daily interval.
5. Daily period label — a static, non-interactive 1D display; no timeframe selector or wheel logic remains.
6. Signal feed and bottom ticker — Media ticker presentation, connected to the A-share daily signal payload.
7. Full-screen dynamic layout — Media viewport/safe-area/orientation system with an A-share panel geometry layer.

## Media parity and A-share adaptations

The shared display behavior is checked against Media commit `601754a7b5033c3380956e2eae7f3efb433ca7d9`. Shared lifecycle modules and card presentation styles are retained; K-line drawing/gesture behavior, responsive layout, logo transitions, ticker animation continuity and card interactions are carried over with A-share-specific adapters. The intentional adaptations are: Tencent daily candles and the five A-share EMA periods; a single 1D selector; 500-stock quote/signal cards; stock name/code and exchange-calendar countdown; and the A-share signal ticker data contract. No Gate market-data or external signal-source dependency is used.

## A-share data
- Market universe: the existing CN500 code list.
- Historical candles: Tencent via AKShare `stock_zh_a_hist_tx`, QFQ daily data.
- Stock names: Tencent quote-name endpoint.
- Incremental cache: per-symbol compressed history with a 14-calendar-day overlap.
- History warm-up: request up to 10 years of daily data; use whatever history Tencent provides, with no minimum-history rejection. EMA periods: 12, 144, 169, 576, 676 only.
- Scan at 16:30 China Standard Time on weekdays, after the A-share close; use today's completed session after 15:30 and the previous session before then.
- Do not publish partial results when Tencent history fetches fail.
- Automatic Bark notifications require the repository Actions secret `BARK_KEY`; `BARK_SERVER` is optional and defaults to `https://api.day.app`.
- Pages data is generated by the scheduled/manual A-share workflow. No credentials are committed.

## Runtime boundaries
- CN is independent. Browser cache and viewport keys use CN-specific namespaces.
- Media remains the source of truth for the seven shared systems and visual assets.
- Tencent is the only configured A-share historical data source in this project.
- The A-share scan and Bark notification run only through the existing scheduled/manual workflow. Ordinary source commits do not send notifications.
